# Web flow and UX objectives — 18 October 2026

Status: **proposed**, except Objectives 1 and 2, which are implemented (see below). Corrected 19 October 2026 after reading the PRD, Design System, Code Style, Architecture, Testing, policy confirmations and the 17–18 October web reports.

Basis: browser review of the in-memory fixture (`web/ui-review.html`, roles `staff`, `head`, `admin`) plus source reading. The fixture dashboards show zeros and skeletons because they use sample/busy states, so those screens are **not** evidence of real empty-state bugs. Local browser use now works, so the actual-browser acceptance that earlier reports left pending can be done.

Constraints for every objective: preserve custody invariants, role permissions, accepted UI preferences (AGENTS.md, Design System) and shared components/tokens. UX only; no workflow or authority change.

## Implemented

### Objective 1 — Request details: honest loading (all roles; Requests page)
- Verifying the exact ticket no longer shows "Saving…"; buttons stay disabled with the status text "Checking the latest details. Actions unlock when this finishes." The word "Saving…" appears only during a real write.
- "Retry request details" appears only when the exact-ticket read actually failed (desktop panel and phone dialog).
- Preserved: decisions stay disabled until the exact ticket loads; full purpose stays readable.
- Test updated: `followup-remediation.test.mjs` now expects Retry only on error.

### Objective 2 — Requests list: next-step cue (all roles; Requests page)
- Each active row shows one subdued line: "Needs your decision" / "Waiting for the receiving office" (pending); "Close when the work is complete" / "In progress" (accepted); for DV, "Record payment release when paid" (Treasury or admin) / "Waiting for Treasury to record release".
- Does not repeat the status pill and does not imply a physical handoff.
- Evidence: 103 web tests, scoped Oxlint exit 0, production build, fixture check. Pixel-level desktop check still pending.
