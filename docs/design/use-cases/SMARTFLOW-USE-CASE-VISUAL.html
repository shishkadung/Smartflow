✓ Valid Transitions
• First scan must be IN
• OUT requires prior IN at same office
• IN at recipient office only
✗ Blocked Actions
• IN when already IN at same office
• OUT without prior IN
• IN at wrong office (not recipient)
• OUT without destination

6. Duplicate Prevention (8-Second Debounce)

1
Staff submits scan
POST /movements-create with document_id, office_id, status, user_id
?
Check recent duplicates
Query: SELECT * FROM movements WHERE document_id=? AND office_id=? AND status=? AND user_id=? AND scanned_at >= NOW() - INTERVAL 8 SECOND
✗
Duplicate found
Log: movement.scan REJECTED
scan_error: duplicate
Response: 409 Conflict
✓
No duplicate
INSERT movement record
Log: movement.scan SUCCESS
Response: 200 OK

7. Error Code Reference

Error Code Category Scenario
qr_tampered Security QR signature invalid - possible forgery
qr_expired Security Token past 180-day TTL - needs reprint
qr_mismatch Security QR doc ≠ scanned doc - wrong label
duplicate Validation Same scan within 8 seconds
already_in_here State Marking IN when already IN at this office
already_out_here State Marking IN when already OUT from this office
still_at_other_office State Marking IN when doc at different office
wrong_receiver State IN scan at office not designated as recipient
not_in_at_office State OUT scan when doc not currently IN here
out_without_in State First scan is OUT (no prior IN exists)
missing_destination Input OUT scan without selecting destination office
same_destination Input Destination = current office
role_forbidden Auth Admin/Accountant tried to scan (not allowed)

8. Complete Document Lifecycle

📁 Creation Phase
• Accounting creates document record
• System generates signed QR token
• Physical folder label printed
🏢 Office A Processing
• Staff scans IN (first receipt) ✓
• Document processed at office
• Staff scans OUT to Office B
🚚 Transit Phase
• Physical transport between offices
• Digital trail: OUT at A (unconfirmed)r> • Alert if not scanned IN within threshold
🏢 Office B Processing
• Staff scans IN (validate: was sent here) ✓
• Document processed at office
• Staff scans OUT to Office C
🏢 Office C Processing
• Department Head scans IN
• Review and approval
• Scan OUT to Accounting (final)
✅ Close Phase
• Accounting scans IN (final receipt)
• Payment processing / filing
• Document archived

SF1 Token Format Reference

Structure: SF1.{base64url(payload)}.{base64url(hmac)}
Payload (JSON):
{
  "d": "DOC-2026-000001",
  "i": 1716912000,
  "e": 1732598400
}
d = document_id | i = issued_at (unix) | e = expires_at (unix)
Signature: HMAC-SHA256(base64url(payload), secret)
